## 2. Теоретическая база

### 2.1. Понятие оконной функции

Оконная функция выполняет вычисление над набором строк, связанных с текущей строкой. Этот набор называется **окном**. В отличие от агрегатной функции с `GROUP BY`, оконная функция **не схлопывает** строки в одну: каждая исходная строка сохраняется в результате, а рядом с ней появляется вычисленное значение.

Например, можно одновременно показать цену товара и его место в рейтинге внутри категории:

```sql
SELECT title, price,
       ROW_NUMBER() OVER (PARTITION BY category_id ORDER BY price DESC) AS rn
FROM products;
```

Оконные функции вычисляются на позднем этапе обработки запроса — после `WHERE`, `GROUP BY` и `HAVING`, но до `ORDER BY` и `LIMIT`. Поэтому в оконной функции уже доступны результаты группировки.

### 2.2. Синтаксис: конструкция `OVER`

Оконная функция всегда записывается с конструкцией `OVER`, которая задаёт окно:

```sql
функция(...) OVER (
    [PARTITION BY столбцы]
    [ORDER BY столбцы]
    [ROWS | RANGE рамка]
)
```

| Элемент | Назначение |
|---|---|
| `PARTITION BY` | делит строки на разделы; функция считается независимо в каждом разделе |
| `ORDER BY` | задаёт порядок строк внутри окна; критичен для ранжирования и накопительных итогов |
| `ROWS` / `RANGE` | задаёт рамку окна относительно текущей строки |

Если `PARTITION BY` опущена, окном считаются все строки результата. Если указан `ORDER BY`, по умолчанию действует рамка `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` — именно она даёт нарастающий итог. Для точного построчного накопления используют `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`.

### 2.3. Ранжирующие функции

| Функция | Поведение при равных значениях | Пример |
|---|---|---|
| `ROW_NUMBER()` | уникальные последовательные номера, равные значения получают разные номера | 1, 2, 3, 4 |
| `RANK()` | равные значения получают одинаковый ранг, следующие номера пропускаются | 1, 1, 3, 4 |
| `DENSE_RANK()` | равные значения получают одинаковый ранг без пропусков | 1, 1, 2, 3 |
| `NTILE(n)` | делит строки на `n` примерно равных групп | 1, 1, 2, 2, 3, 3 |

Пример ранжирования товаров по цене внутри категории:

```sql
SELECT c.name AS category,
       p.title,
       p.price,
       ROW_NUMBER() OVER w AS rn,
       RANK()       OVER w AS rnk,
       DENSE_RANK() OVER w AS dense_rnk
FROM products AS p
JOIN categories AS c ON c.id = p.category_id
WINDOW w AS (PARTITION BY p.category_id ORDER BY p.price DESC);
```

### 2.4. Агрегатные функции в роли оконных

Любую агрегатную функцию можно использовать как оконную, добавив `OVER`:

```sql
SUM(oi.quantity * oi.unit_price) OVER (PARTITION BY p.category_id) AS category_revenue
```

Такая конструкция возвращает сумму по разделу **в каждой строке**, не убирая детальные строки. Деление значения строки на сумму по разделу даёт долю в группе.

Если добавить `ORDER BY` внутрь окна, получается **нарастающий итог**:

```sql
SUM(SUM(oi.quantity * oi.unit_price))
    OVER (ORDER BY o.created_at::date) AS running_total
```

Здесь внешняя `SUM` — оконная, внутренняя — обычная агрегатная функция после `GROUP BY`.

### 2.5. Функции смещения

`LAG(столбец)` возвращает значение из предыдущей строки окна, `LEAD(столбец)` — из следующей:

```sql
LAG(revenue)  OVER (ORDER BY day) AS prev_day,
LEAD(revenue) OVER (ORDER BY day) AS next_day
```

Они применяются для сравнения с предыдущим периодом, расчёта прироста, поиска изменений. Если предыдущей/следующей строки нет, возвращается `NULL`. Можно задать смещение и значение по умолчанию: `LAG(revenue, 1, 0)`.

`FIRST_VALUE` и `LAST_VALUE` возвращают первое и последнее значение в рамке окна. Для `LAST_VALUE` важно явно задать рамку, иначе по умолчанию последней строкой будет текущая.

### 2.6. Топ-N в группе

Частая задача — отобрать несколько лучших строк в каждой группе. Её решают так:

1. оконной функцией `ROW_NUMBER()` нумеруют строки внутри раздела по нужному порядку;
2. во внешнем запросе или CTE оставляют строки с номером не больше `N`.

```sql
WITH ranked AS (
    SELECT p.*,
           ROW_NUMBER() OVER (
               PARTITION BY p.category_id
               ORDER BY p.price DESC
           ) AS rn
    FROM products AS p
)
SELECT * FROM ranked WHERE rn <= 3;
```

Если при равных значениях нужно включить все «пограничные» строки, используют `RANK()` вместо `ROW_NUMBER()`.

### 2.7. Оконная функция или `GROUP BY`

| Критерий | `GROUP BY` | Оконная функция |
|---|---|---|
| Детальные строки | теряются, остаются только группы | сохраняются |
| Сводный показатель рядом с деталью | требует соединения с подзапросом | вычисляется сразу |
| Читаемость | проще для чистых агрегатов | проще для «деталь + итог» |
| Производительность | часто эффективнее для сводки | может быть дороже из-за сортировки окна |

Оконная функция предпочтительнее, когда нужны **и детальные строки, и сводный показатель**: рейтинг, доля в группе, нарастающий итог, сравнение с соседней строкой. `GROUP BY` удобнее, когда нужен только итог по группам.

### 5.1. Запрос 1. Рейтинг товаров по цене внутри категории

#### 5.1a. Демонстрация различий на равных ценах

**Назначение:** показать, как ведут себя `ROW_NUMBER`, `RANK` и `DENSE_RANK`, когда у двух товаров одинаковая цена.

```sql
WITH demo (category, title, price) AS (
    VALUES
        ('Смартфоны', 'Модель A', 1000),
        ('Смартфоны', 'Модель B', 1000),
        ('Смартфоны', 'Модель C', 900),
        ('Смартфоны', 'Модель D', 800)
)
SELECT category,
       title,
       price,
       ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC) AS row_number,
       RANK()       OVER (PARTITION BY category ORDER BY price DESC) AS rank,
       DENSE_RANK() OVER (PARTITION BY category ORDER BY price DESC) AS dense_rank
FROM demo
ORDER BY price DESC, title;
```

**Результат:**

| category | title | price | row_number | rank | dense_rank |
|---|---|---:|---:|---:|---:|
| Смартфоны | Модель A | 1000 | 1 | 1 | 1 |
| Смартфоны | Модель B | 1000 | 2 | 1 | 1 |
| Смартфоны | Модель C | 900 | 3 | 3 | 2 |
| Смартфоны | Модель D | 800 | 4 | 4 | 3 |

**Пояснение:**

- `ROW_NUMBER` присваивает уникальные номера даже равным строкам: A — 1, B — 2;
- `RANK` даёт равным строкам одинаковый ранг 1, но следующая строка получает ранг 3 — номер 2 «пропускается»;
- `DENSE_RANK` также даёт A и B ранг 1, но следующая строка получает 2 — без пропусков.

#### 5.1b. Рейтинг реальных товаров категории «Смартфоны»

**Назначение:** пронумеровать активные товары категории 2 по убыванию цены тремя способами.

### 5.2. Запрос 2. Три самых дорогих товара в каждой категории

**Назначение:** пронумеровать активные товары внутри каждой категории по убыванию цены и оставить только первые три номера.

```sql
WITH ranked AS (
    SELECT p.id,
           p.title,
           c.name AS category,
           p.price,
           ROW_NUMBER() OVER (
               PARTITION BY p.category_id
               ORDER BY p.price DESC, p.id
           ) AS rn
    FROM products AS p
    JOIN categories AS c ON c.id = p.category_id
    WHERE p.is_active = TRUE
)
SELECT category,
       rn,
       title,
       price
FROM ranked
WHERE rn <= 3
ORDER BY category, rn;
```

|---|---:|---|---:|
| Аудиотехника | 1 | Наушники №1182 | 9934.00 |
| Аудиотехника | 2 | Наушники №525 | 9925.00 |
| Аудиотехника | 3 | Наушники №984 | 9808.00 |
| Женская одежда | 1 | Женское платье №1051 | 9987.00 |
| Женская одежда | 2 | Женское платье №394 | 9978.00 |
| Женская одежда | 3 | Женское платье №853 | 9861.00 |
| Книги | 1 | Книга №854 | 9998.00 |
| Книги | 2 | Книга №197 | 9989.00 |
| Книги | 3 | Книга №656 | 9872.00 |

### 5.3. Запрос 3. Нарастающий итог выручки по дням

**Назначение:** посчитать выручку каждого дня и накопительную сумму с начала периода.

```sql
SELECT o.created_at::date AS day,
       SUM(oi.quantity * oi.unit_price) AS day_revenue,
       SUM(SUM(oi.quantity * oi.unit_price))
           OVER (ORDER BY o.created_at::date) AS running_total
FROM orders AS o
JOIN order_items AS oi ON oi.order_id = o.id
WHERE o.status <> 'cancelled'
```

| 2024-10-27 | 109366.00 | 454002.00 |
| 2024-10-29 | 114262.00 | 568264.00 |
| 2024-10-30 | 115518.00 | 683782.00 |
| 2024-10-31 | 133756.00 | 817538.00 |
| 2024-11-01 | 113476.00 | 931014.00 |
| 2024-11-03 | 121382.00 | 1052396.00 |
| 2024-11-04 | 119018.00 | 1171414.00 |
| 2024-11-05 | 106636.00 | 1278050.00 |

**Пояснение:** внутренняя `SUM(oi.quantity * oi.unit_price)` агрегирует выручку по дню. Внешняя `SUM(...) OVER (ORDER BY day)` накапливает значения от первой строки окна до текущей. В датах есть пропуски: дни без неотменённых заказов отсутствуют, поэтому нарастающий итог считается по фактическим дням с выручкой.

### 5.4. Запрос 4. Доля выручки продавца в выручке его категории

**Назначение:** для каждой пары «категория — продавец» показать выручку, общую выручку категории и процентную долю продавца.

```sql
WITH seller_category AS (
    SELECT p.category_id,
           p.seller_id,
           SUM(oi.quantity * oi.unit_price) AS revenue
    FROM products AS p
    JOIN order_items AS oi ON oi.product_id = p.id
    JOIN orders AS o      ON o.id = oi.order_id
    WHERE o.status <> 'cancelled'
    GROUP BY p.category_id, p.seller_id
)
SELECT c.name AS category,
       s.store_name AS seller,
       sc.revenue,
       SUM(sc.revenue) OVER (PARTITION BY sc.category_id) AS category_revenue,
       ROUND(sc.revenue
             / SUM(sc.revenue) OVER (PARTITION BY sc.category_id) * 100, 2) AS share_pct
FROM seller_category AS sc
JOIN categories AS c ON c.id = sc.category_id
JOIN sellers    AS s ON s.id = sc.seller_id
ORDER BY category, share_pct DESC
LIMIT 20;
```

| Аудиотехника | Магазин №19 | 805924.00 | 6999671.00 | 11.51 |
| Аудиотехника | Магазин №28 | 797371.00 | 6999671.00 | 11.39 |
| Аудиотехника | Магазин №25 | 791618.00 | 6999671.00 | 11.31 |
| Аудиотехника | Магазин №4 | 783432.00 | 6999671.00 | 11.19 |
| Аудиотехника | Магазин №10 | 767451.00 | 6999671.00 | 10.96 |
| Аудиотехника | Магазин №7 | 751618.00 | 6999671.00 | 10.74 |
| Аудиотехника | Магазин №13 | 743868.00 | 6999671.00 | 10.63 |
| Аудиотехника | Магазин №1 | 374030.00 | 6999671.00 | 5.34 |
| Аудиотехника | Магазин №16 | 362680.00 | 6999671.00 | 5.18 |

**Пояснение:** CTE `seller_category` сначала агрегирует выручку до уровня «категория + продавец». Затем `SUM(sc.revenue) OVER (PARTITION BY sc.category_id)` возвращает общую выручку категории **в каждой строке** этого раздела — без схлопывания строк. Деление выручки продавца на общую выручку категории даёт долю; сумма долей продавцов внутри одной категории равна 100%. В одной категории работают около 10 продавцов, поэтому доли в основном 4–13%.

### 5.5. Запрос 5. `LAG` и `LEAD`: сравнение выручки соседних дней

**Назначение:** для каждого дня показать выручку, выручку предыдущего и следующего дня, абсолютный и процентный прирост.

```sql
WITH daily AS (
    SELECT o.created_at::date AS day,
           SUM(oi.quantity * oi.unit_price) AS revenue
    FROM orders AS o
    JOIN order_items AS oi ON oi.order_id = o.id
    WHERE o.status <> 'cancelled'
    GROUP BY o.created_at::date
)
SELECT day,
       revenue,
       LAG(revenue)  OVER (ORDER BY day) AS prev_day,
       revenue - LAG(revenue) OVER (ORDER BY day) AS growth_abs,
       ROUND((revenue - LAG(revenue) OVER (ORDER BY day))
             / NULLIF(LAG(revenue) OVER (ORDER BY day), 0) * 100, 2) AS growth_pct,
       LEAD(revenue) OVER (ORDER BY day) AS next_day
FROM daily
ORDER BY day DESC
LIMIT 15;
```

| 2026-10-21 | 189354.00 | 154827.00 | 34527.00 | 22.30 | 98056.00 |
| 2026-10-20 | 154827.00 | 147273.00 | 7554.00 | 5.13 | 189354.00 |
| 2026-10-19 | 147273.00 | 149664.00 | -2391.00 | -1.60 | 154827.00 |
| 2026-10-17 | 149664.00 | 189534.00 | -39870.00 | -21.04 | 147273.00 |

**Пояснение:** `LAG(revenue)` возвращает выручку предыдущей строки окна, `LEAD(revenue)` — следующей. `growth_abs` — абсолютный прирост, `growth_pct` — процентный; `NULLIF(..., 0)` защищает от деления на ноль. У первой строки результата (самый поздний день) `LEAD` равен `NULL`, потому что следующей строки нет. Важно: поскольку в данных есть пропуски дат, `LAG` берёт предыдущий **день с выручкой**, а не обязательно предыдущий календарный день; для строгого сравнения по календарю нужен `generate_series` и `LEFT JOIN`.

### 5.6. Запрос 6. Та же задача через `GROUP BY`

**Назначение:** решить задачу из раздела 5.4 без оконной функции — через два уровня агрегации и соединение.

```sql
WITH seller_category AS (
    SELECT p.category_id,
           p.seller_id,
           SUM(oi.quantity * oi.unit_price) AS revenue
    FROM products AS p
    JOIN order_items AS oi ON oi.product_id = p.id
    JOIN orders AS o      ON o.id = oi.order_id
    WHERE o.status <> 'cancelled'
    GROUP BY p.category_id, p.seller_id
),
category_total AS (
    SELECT category_id,
           SUM(revenue) AS category_revenue
    FROM seller_category
    GROUP BY category_id
)
SELECT c.name AS category,
       s.store_name AS seller,
       sc.revenue,
       ct.category_revenue,
       ROUND(sc.revenue / ct.category_revenue * 100, 2) AS share_pct
FROM seller_category AS sc
JOIN category_total AS ct ON ct.category_id = sc.category_id
JOIN categories AS c      ON c.id = sc.category_id
JOIN sellers    AS s      ON s.id = sc.seller_id
ORDER BY category, share_pct DESC
LIMIT 15;
```

## 7. Ответы на контрольные вопросы

### 1. Что такое оконная функция и чем она отличается от агрегатной функции с `GROUP BY`?

Оконная функция вычисляет значение по набору строк, связанных с текущей (окну), но **не схлопывает** строки: каждая исходная строка остаётся в результате, а рядом появляется вычисленное значение. Агрегатная функция с `GROUP BY` возвращает одну строку на группу и теряет детализацию. Например, `SUM(price) OVER (PARTITION BY category_id)` показывает сумму категории в каждой строке товара, а `SUM(price) ... GROUP BY category_id` — только по одной строке на категорию.

### 2. За что отвечает конструкция `OVER`?

`OVER` задаёт окно — набор строк, по которому вычисляется функция. Внутри `OVER` указываются `PARTITION BY` (разделы), `ORDER BY` (порядок строк) и рамка (`ROWS`/`RANGE`). Без `OVER` функция была бы обычной агрегатной; с `OVER` она становится оконной.

### 3. Что задаёт секция `PARTITION BY` и чем она похожа и непохожа на `GROUP BY`?

`PARTITION BY` делит строки на независимые разделы, внутри каждого функция считается отдельно. Это похоже на `GROUP BY`: в обоих случаях данные разбиваются на группы. Но `GROUP BY` **объединяет** строки группы в одну, а `PARTITION BY` оставляет все строки и лишь помечает их принадлежность к разделу. Если `PARTITION BY` не указана, окном считаются все строки результата.

### 4. Для чего нужна секция `ORDER BY` внутри `OVER`?

`ORDER BY` задаёт порядок строк внутри окна. Он критичен для ранжирующих функций (`ROW_NUMBER`, `RANK`, `DENSE_RANK`), функций смещения (`LAG`, `LEAD`) и накопительных итогов (`SUM ... OVER (ORDER BY day)`). Без `ORDER BY` понятие «предыдущая строка» или «нарастающий итог» не определено.

### 5. Чем различаются `ROW_NUMBER`, `RANK` и `DENSE_RANK` на строках с равными значениями?

`ROW_NUMBER` присваивает уникальные последовательные номера даже равным строкам: 1, 2, 3, 4. `RANK` даёт равным строкам одинаковый ранг, но пропускает следующие номера: 1, 1, 3, 4. `DENSE_RANK` даёт равным строкам одинаковый ранг без пропусков: 1, 1, 2, 3. Это показано в запросе 5.1a.

### 6. Как с помощью оконной функции отобрать N лучших строк в каждой группе?

Нужно пронумеровать строки внутри группы (`PARTITION BY группа ORDER BY критерий`) функцией `ROW_NUMBER`, затем во внешнем запросе или CTE оставить `rn <= N`. Пример — запрос 2: три самых дорогих товара в каждой категории. Если при равных значениях нужно включить все пограничные строки, используют `RANK` вместо `ROW_NUMBER`.

### 7. Как использовать агрегатную функцию в роли оконной и какой результат это даёт?

Нужно добавить к агрегатной функции конструкцию `OVER`, например `SUM(price) OVER (PARTITION BY category_id)`. Тогда агрегат вычисляется по разделу, но возвращается в каждой строке, а не одной строкой на группу. Это позволяет одновременно видеть деталь и сводный показатель: цену товара и среднюю цену категории, выручку продавца и выручку категории.

### 8. Что такое нарастающий итог и как его получить оконной функцией?

Нарастающий итог — сумма значений от начала периода до текущей строки. Получается агрегатной функцией с `ORDER BY` внутри окна:

```sql
SUM(revenue) OVER (ORDER BY day) AS running_total
```

По умолчанию действует рамка `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`. Для точного построчного накопления при одинаковых значениях ключа используют `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`. Пример — запрос 3.

### 9. Что делают функции `LAG` и `LEAD` и для каких задач применяются?

`LAG` возвращает значение из предыдущей строки окна, `LEAD` — из следующей. Они применяются для сравнения с предыдущим/следующим периодом, расчёта прироста, поиска изменений, анализа трендов. Можно задать смещение и значение по умолчанию. Если строки нет, возвращается `NULL`. Пример — запрос 5.

### 10. В каких случаях оконная функция предпочтительнее обычной группировки?

Когда нужны **и детальные строки, и сводный показатель**: рейтинг внутри группы, доля в группе, нарастающий итог, сравнение с соседней строкой, топ-N. Оконная функция сохраняет детализацию и часто позволяет обойтись без дополнительных CTE и соединений. `GROUP BY` предпочтительнее, когда нужен только итог по группам и детальные строки не важны — тогда он проще и может быть эффективнее.
