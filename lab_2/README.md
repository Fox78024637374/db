## 2. Теоретическая база

### 2.1. Структура команды `SELECT`

Команда `SELECT` состоит из секций, каждая из которых отвечает за свой этап обработки данных:

```sql
SELECT   [DISTINCT] список_столбцов
FROM     источник
WHERE    условие_фильтрации_строк
GROUP BY столбцы_группировки
HAVING   условие_фильтрации_групп
ORDER BY столбцы_сортировки [ASC | DESC]
LIMIT    количество OFFSET смещение;
```

**Порядок записи не совпадает с порядком выполнения.** Логически СУБД обрабатывает запрос так:

```
FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT/OFFSET
```

| Этап | Что происходит |
|---|---|
| `FROM` | определяется источник строк, выполняются соединения |
| `WHERE` | отбрасываются строки, для которых условие не истинно |
| `GROUP BY` | строки объединяются в группы |
| `HAVING` | отбрасываются группы, не удовлетворяющие условию |
| `SELECT` | вычисляется список выборки, формируются псевдонимы |
| `DISTINCT` | удаляются полностью совпадающие строки результата |
| `ORDER BY` | результат сортируется |
| `LIMIT/OFFSET` | возвращается нужная страница |

Из этого порядка следуют важные правила:

- псевдоним, заданный в `SELECT`, **доступен** в `ORDER BY`, но **недоступен** в `WHERE` — на момент выполнения `WHERE` список выборки ещё не вычислен;
- `WHERE` фильтрует строки **до** группировки, а `HAVING` — уже сгруппированные данные;
- без `ORDER BY` порядок строк не гарантирован, даже если визуально он кажется стабильным.

### 2.2. Фильтрация строк: `WHERE` и предикаты

Секция `WHERE` задаёт логическое условие. В результат попадают только те строки, для которых условие принимает значение **TRUE**.

| Предикат | Назначение | Пример |
|---|---|---|
| `=`, `<>`, `<`, `>`, `<=`, `>=` | сравнение значений | `price >= 1000` |
| `BETWEEN a AND b` | замкнутый диапазон, включает границы | `price BETWEEN 1000 AND 5000` |
| `IN (...)` | принадлежность списку значений | `status IN ('paid','shipped')` |
| `LIKE` | поиск по шаблону с учётом регистра | `title LIKE 'Смартфон%'` |
| `ILIKE` | поиск по шаблону без учёта регистра | `title ILIKE '%смартфон%'` |
| `IS NULL` / `IS NOT NULL` | проверка отсутствия/наличия значения | `description IS NULL` |

В шаблоне `LIKE`:

- `%` — любая последовательность символов, в том числе пустая;
- `_` — ровно один произвольный символ;
- чтобы искать сам символ `%` или `_`, используется `ESCAPE`.

Сложные условия объединяются операторами `AND`, `OR`, `NOT`. Приоритет: `NOT` → `AND` → `OR`. Скобки меняют порядок вычисления и делают логику явной:

```sql
WHERE (category_id = 2 OR category_id = 3)
  AND is_active = TRUE
```

Без скобок условие читалось бы иначе: `AND` связывает сильнее, поэтому `category_id = 2 OR (category_id = 3 AND is_active = TRUE)` — это уже другая выборка.

### 2.3. Значение `NULL` и трёхзначная логика

`NULL` означает **отсутствие значения** («неизвестно» или «неприменимо»), а не ноль и не пустую строку. Поэтому `NULL` не равен даже самому себе:

```sql
NULL = NULL      -- UNKNOWN, а не TRUE
```

SQL использует трёхзначную логику: результат сравнения может быть **TRUE**, **FALSE** или **UNKNOWN**.

| A | B | `A AND B` | `A OR B` |
|---|---|---|---|
| TRUE | UNKNOWN | UNKNOWN | TRUE |
| FALSE | UNKNOWN | FALSE | UNKNOWN |
| UNKNOWN | UNKNOWN | UNKNOWN | UNKNOWN |

Строки, для которых `WHERE` даёт `UNKNOWN`, в результат **не попадают**. Поэтому для проверки отсутствия значения применяют специальные предикаты `IS NULL` и `IS NOT NULL`, а для подстановки значения по умолчанию — функцию `COALESCE`:

```sql
SELECT title, COALESCE(description, 'Описание не указано') AS description
FROM products
WHERE description IS NULL;
```

### 2.4. Сортировка, ограничение и уникальность

**`ORDER BY`** сортирует результат по одному или нескольким столбцам и выражениям:

- `ASC` — по возрастанию (по умолчанию), `DESC` — по убыванию;
- для каждого ключа можно отдельно указать `NULLS FIRST` или `NULLS LAST`;
- сортировать можно по псевдониму из `SELECT` или по порядковому номеру столбца.

```sql
ORDER BY category_id ASC, price DESC
```

**`LIMIT` и `OFFSET`** ограничивают количество строк и задают смещение. Вместе они реализуют постраничный вывод:

```sql
LIMIT 20 OFFSET 20   -- вторая страница по 20 записей
```

Для стабильной пагинации сортировка должна быть **детерминированной**: если значения ключа повторяются, в конец ключа добавляют уникальный столбец, например `id`.

**`DISTINCT`** убирает полностью совпадающие строки результата. Важно: `DISTINCT` применяется ко **всему** списку выборки, а не к отдельному столбцу. Конструкция `DISTINCT ON (столбец)` оставляет по одной строке на каждое значение указанного столбца — это расширение PostgreSQL.

### 2.5. Наполнение таблиц данными

Для вставки строк используется `INSERT`:

```sql
INSERT INTO categories (name) VALUES ('Электроника'), ('Книги');

INSERT INTO products (seller_id, category_id, title, price)
SELECT 1,
       2,
       'Товар №' || g,
       (1000 + g * 10)::numeric(12, 2)
FROM generate_series(1, 1000) AS g;
```

`INSERT ... SELECT` позволяет получить данные из запроса, а `generate_series` — сгенерировать последовательность чисел для массового заполнения. В учебной работе вместо `random()` удобнее детерминированные выражения: тогда при повторном запуске скрипта получаются те же самые данные и результаты запросов воспроизводимы.

При явной вставке идентификаторов в столбцы `GENERATED ALWAYS AS IDENTITY` используется `OVERRIDING SYSTEM VALUE`, а после вставки счётчик синхронизируется:

```sql
SELECT setval(pg_get_serial_sequence('products', 'id'),
              (SELECT max(id) FROM products));
```

## 4. Наполнение базы тестовыми данными

### 4.1. Подход к генерации

Скрипт [`lab_2seed.sql`](./lab_2seed.sql) устроен так:

- **Идемпотентность.** В начале выполняется `TRUNCATE ... RESTART IDENTITY CASCADE`, поэтому скрипт можно запускать повторно — данные каждый раз создаются заново, а счётчики `IDENTITY` обнуляются.
- **Транзакция.** Все вставки обёрнуты в `BEGIN ... COMMIT`: при ошибке база не останется в частично заполненном состоянии.
- **Детерминированность.** Вместо `random()` используются арифметические выражения от номера строки (`g % 30`, `g * 137 % 9000`). Это даёт псевдослучайное, но воспроизводимое распределение.
- **Явные идентификаторы.** Для связанных таблиц ID задаются явно через `OVERRIDING SYSTEM VALUE`, чтобы внешние ключи были предсказуемыми.
- **Массовость.** Крупные таблицы заполняются через `generate_series` и `INSERT ... SELECT`.
- **Согласованность.** Суммы заказов рассчитываются по позициям, платежи создаются только для оплаченных заказов, доставки — только для отправленных и доставленных.

### 4.3. Ключевые фрагменты скрипта

**Пользователи.** Роль определяется номером строки, поэтому состав ролей заранее известен:

```sql
INSERT INTO users (id, full_name, email, phone, role, created_at)
OVERRIDING SYSTEM VALUE
SELECT g,
       'Пользователь ' || g,
       'user' || g || '@example.com',
       '+7' || (9000000000 + g)::text,
       CASE
           WHEN g = 1 THEN 'admin'
           WHEN g <= 31 THEN 'seller'
           ELSE 'buyer'
       END,
       now() - ((g % 365) || ' days')::interval
FROM generate_series(1, 200) AS g;
```

**Товары.** Каждый товар получает продавца, категорию, название по категории, цену и признак активности. Каждый седьмой товар остаётся без описания — это понадобится для проверки `IS NULL`:

```sql
WITH cats AS (
    SELECT ARRAY[2, 3, 4, 6, 7, 9, 10, 11, 12] AS ids
)
INSERT INTO products (id, seller_id, category_id, title, description,
                      price, is_active, created_at)
OVERRIDING SYSTEM VALUE
SELECT g,
       1 + ((g * 7) % 30),
       c.ids[1 + ((g - 1) % array_length(c.ids, 1))],
       CASE c.ids[1 + ((g - 1) % array_length(c.ids, 1))]
           WHEN 2  THEN 'Смартфон'
           WHEN 3  THEN 'Ноутбук'
           WHEN 4  THEN 'Наушники'
           WHEN 6  THEN 'Блендер'
           WHEN 7  THEN 'Пылесос'
           WHEN 9  THEN 'Мужская куртка'
           WHEN 10 THEN 'Женское платье'
           WHEN 11 THEN 'Книга'
           ELSE 'Спортивный товар'
       END || ' №' || g,
       CASE WHEN g % 7 = 0 THEN NULL ELSE 'Описание товара №' || g END,
       (1000 + ((g * 137) % 9000))::numeric(12, 2),
       (g % 11 <> 0),
       now() - ((g % 500) || ' days')::interval
FROM generate_series(1, 1200) AS g
CROSS JOIN cats AS c;
```

**Заказы.** 1500 заказов распределяются между покупателями и пятью статусами:

```sql
INSERT INTO orders (id, user_id, status, total_amount, created_at)
OVERRIDING SYSTEM VALUE
SELECT g,
       32 + ((g * 7) % 169),
       (ARRAY['created', 'paid', 'shipped', 'delivered', 'cancelled'])[1 + (g % 5)],
       0,
       now() - ((g % 730) || ' days')::interval
FROM generate_series(1, 1500) AS g;
```

**Позиции заказов.** В каждом заказе три разных товара; цена фиксируется на момент покупки:

```sql
INSERT INTO order_items (order_id, product_id, quantity, unit_price)
SELECT o.id,
       p.id,
       1 + ((o.id + k) % 5),
       p.price
FROM orders AS o
CROSS JOIN generate_series(1, 3) AS k
JOIN products AS p
  ON p.id = 1 + (((o.id * 53) + (k * 311)) % 1200);
```

**Сумма заказа.** После вставки позиций сумма пересчитывается, чтобы не хранить несогласованное значение:

```sql
UPDATE orders AS o
SET total_amount = COALESCE(
        (SELECT SUM(oi.quantity * oi.unit_price)
         FROM order_items AS oi
         WHERE oi.order_id = o.id), 0);
```

**Платежи и доставки.** Создаются только для тех статусов, где они имеют смысл:

```sql
INSERT INTO payments (order_id, amount, status, paid_at)
SELECT o.id,
       o.total_amount,
       CASE WHEN o.id % 17 = 0 THEN 'pending' ELSE 'completed' END,
       CASE WHEN o.id % 17 = 0 THEN NULL
            ELSE o.created_at + interval '10 minutes' END
FROM orders AS o
WHERE o.status IN ('paid', 'shipped', 'delivered');

INSERT INTO deliveries (order_id, address_id, delivery_status, delivery_date)
SELECT o.id,
       (SELECT a.id FROM addresses AS a
        WHERE a.user_id = o.user_id ORDER BY a.id LIMIT 1),
       CASE WHEN o.status = 'delivered' THEN 'delivered' ELSE 'in_transit' END,
       CASE WHEN o.status = 'delivered'
            THEN o.created_at + interval '3 days' END
FROM orders AS o
WHERE o.status IN ('shipped', 'delivered');
```

## 5. Запросы на выборку и фильтрацию

Все запросы находятся в файле [`lab_2queries.sql`](./lab_2queries.sql). Ниже для каждого приведены назначение, текст и реальный фрагмент результата.

### 5.1. Запрос 1. `DISTINCT` и псевдонимы столбцов

**Назначение:** получить уникальные пары «продавец — категория», то есть показать, какие сочетания продавцов и категорий реально встречаются в каталоге, без повторяющихся строк. Псевдонимы `seller_id` и `category_id` заданы через `AS`.

```sql
SELECT DISTINCT p.seller_id  AS seller_id,
                p.category_id AS category_id
FROM products AS p
ORDER BY p.seller_id, p.category_id
LIMIT 15;
```

**Результат (фрагмент):**

| seller_id | category_id |
|---:|---:|
| 1 | 4 |
| 1 | 9 |
| 1 | 12 |
| 2 | 2 |
| 2 | 6 |
| 2 | 10 |
| 3 | 3 |
| 3 | 7 |
| 3 | 11 |
| 4 | 4 |

**Пояснение:** в `products` 1200 строк, но пар «продавец — категория» значительно меньше. `DISTINCT` применяется ко всему списку выборки и убирает повторяющиеся сочетания. Без `DISTINCT` каждая пара встретилась бы столько раз, сколько товаров у данного продавца в данной категории.

### 5.2. Запрос 2. Несколько условий с `AND`, `OR` и скобками

**Назначение:** выбрать активные товары из категорий «Смартфоны» (2) или «Ноутбуки» (3), цена которых не ниже 3000 рублей. Скобки задают приоритет: сначала объединяется условие по категориям, затем оно пересекается с условиями по активности и цене.

```sql
SELECT p.id,
       p.title,
       p.price,
       p.category_id
FROM products AS p
WHERE (p.category_id = 2 OR p.category_id = 3)
  AND p.is_active = TRUE
  AND p.price >= 3000
ORDER BY p.price DESC
LIMIT 15;
```

**Результат (фрагмент):**

| id | title | price | category_id |
|---:|---|---:|---:|
| 722 | Ноутбук №722 | 9914.00 | 3 |
| 65 | Ноутбук №65 | 9905.00 | 3 |
| 919 | Смартфон №919 | 9903.00 | 2 |
| 262 | Смартфон №262 | 9894.00 | 2 |
| 1181 | Ноутбук №1181 | 9797.00 | 3 |
| 524 | Ноутбук №524 | 9788.00 | 3 |
| 721 | Смартфон №721 | 9777.00 | 2 |
| 64 | Смартфон №64 | 9768.00 | 2 |

**Пояснение:** если убрать скобки, условие превратится в `category_id = 2 OR (category_id = 3 AND is_active = TRUE AND price >= 3000)`, и в результат попадут все смартфоны, включая неактивные и дешёвые. Скобки устраняют эту неоднозначность.

### 5.3. Запрос 3. Предикат `BETWEEN`

**Назначение:** выбрать товары с ценой в замкнутом диапазоне от 1000 до 5000 рублей включительно и отсортировать их по возрастанию цены.

```sql
SELECT p.id,
       p.title,
       p.price
FROM products AS p
WHERE p.price BETWEEN 1000 AND 5000
ORDER BY p.price
LIMIT 15;
```

**Результат (фрагмент):**

| id | title | price |
|---:|---|---:|
| 657 | Спортивный товар №657 | 1009.00 |
| 460 | Смартфон №460 | 1020.00 |

### 5.4. Запрос 4. Предикат `IN`

**Назначение:** выбрать заказы, находящиеся в одном из трёх «рабочих» статусов: оплачен, отправлен, доставлен. Это демонстрирует проверку принадлежности значения списку.

```sql
SELECT o.id,
       o.user_id,
       o.status,
       o.total_amount
FROM orders AS o
WHERE o.status IN ('paid', 'shipped', 'delivered')
ORDER BY o.created_at DESC
LIMIT 15;
```

**Результат (фрагмент):**

| id | user_id | status | total_amount |
|---:|---:|---|---:|
| 1 | 39 | paid | 38558.00 |
| 1461 | 119 | paid | 79478.00 |
| 731 | 79 | paid | 71318.00 |
| 1462 | 126 | shipped | 50109.00 |
| 732 | 86 | shipped | 69809.00 |
| 2 | 46 | shipped | 34909.00 |
| 733 | 93 | delivered | 51291.00 |
| 3 | 53 | delivered | 35251.00 |

**Пояснение:** `status IN ('paid', 'shipped', 'delivered')` заменяет цепочку `status = 'paid' OR status = 'shipped' OR status = 'delivered'`. Список может содержать произвольное число значений; `NOT IN` работает как отрицание.

### 5.5. Запрос 5. Предикат `ILIKE`

## 7. Ответы на контрольные вопросы

### 1. Из каких секций состоит команда `SELECT` и в каком порядке они логически выполняются?

Секции: `SELECT`, `FROM`, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`, `LIMIT`/`OFFSET`; дополнительно `DISTINCT`. Логический порядок выполнения: `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `DISTINCT` → `ORDER BY` → `LIMIT`/`OFFSET`. Порядок записи другой, поэтому псевдоним из `SELECT` не виден в `WHERE`, но виден в `ORDER BY`.

### 2. Почему в промышленных запросах не рекомендуется использовать `SELECT *`?

`SELECT *` передаёт все столбцы, включая те, которые не нужны приложению, — это лишний трафик и память. При изменении схемы (добавлении столбца) результат запроса неожиданно меняется, а код, который рассчитывает на фиксированный набор полей, может сломаться. Кроме того, `*` мешает использовать покрывающий индекс и затрудняет чтение запроса. Надёжнее явно перечислять нужные столбцы.

### 3. Для чего предназначена секция `WHERE` и как в ней комбинируются условия?

`WHERE` фильтрует исходные строки до группировки: в результат попадают только строки, для которых условие истинно. Условия комбинируются операторами `AND`, `OR`, `NOT`; приоритет — `NOT`, затем `AND`, затем `OR`. Скобки задают нужный порядок и устраняют неоднозначность.

### 4. Чем предикаты `BETWEEN` и `IN` отличаются от записи тех же условий через операторы сравнения и `OR`?

`BETWEEN a AND b` эквивалентен `x >= a AND x <= b` и включает обе границы. `IN (a, b, c)` эквивалентен `x = a OR x = b OR x = c`. Обе конструкции короче, лучше читаются и снижают риск ошибки при большом числе значений. При этом `BETWEEN` чувствителен к типу данных и границам, а `IN` с `NULL` в списке может дать неожиданный `UNKNOWN` для `NOT IN`.

### 5. Как работает оператор `LIKE` и что означают символы `%` и `_` в шаблоне?

`LIKE` сравнивает строку с шаблоном: `%` соответствует любой последовательности символов (включая пустую), `_` — ровно одному символу. Например, `'Смартфон%'` — строки, начинающиеся со слова «Смартфон», `'_ук'` — три символа, оканчивающиеся на «ук». `ILIKE` делает то же без учёта регистра. Для поиска самих символов `%` и `_` используется `ESCAPE`.

### 6. Что такое трёхзначная логика и почему нельзя проверять значение на `NULL` оператором «=»?

В SQL результат сравнения может быть `TRUE`, `FALSE` или `UNKNOWN`. `NULL` означает отсутствие значения, поэтому `NULL = NULL` даёт `UNKNOWN`, а не `TRUE`: неизвестное нельзя считать равным другому неизвестному. Строки с `UNKNOWN` в `WHERE` отбрасываются. Для проверки используют `IS NULL` и `IS NOT NULL`.

### 7. Что делает секция `ORDER BY` и как задать сортировку по убыванию и положение `NULL`?

`ORDER BY` сортирует результат по одному или нескольким столбцам/выражениям. Направление задаётся `ASC` (по умолчанию) или `DESC` для каждого ключа отдельно. Положение `NULL` задаётся `NULLS FIRST` или `NULLS LAST`. Сортировать можно по псевдониму из `SELECT` или по номеру столбца. Для стабильного результата при равных значениях добавляют уникальный ключ, например `id`.

### 8. Для чего служат `LIMIT` и `OFFSET` и как с их помощью организовать постраничный вывод?

`LIMIT n` ограничивает число возвращаемых строк, `OFFSET m` пропускает первые `m` строк. Страница размера `n` с номером `k` (начиная с нуля) получается как `LIMIT n OFFSET k * n`. Чтобы страницы не пересекались, нужен детерминированный `ORDER BY`. Большие `OFFSET` неэффективны: СУБД вычисляет и отбрасывает пропущенные строки, поэтому в высоконагруженных системах применяют пагинацию по ключу.

### 9. Что делает ключевое слово `DISTINCT`?

`DISTINCT` удаляет из результата полностью совпадающие строки, оставляя по одной копии. Оно применяется ко всему списку выборки, а не к отдельному столбцу. В PostgreSQL есть также `DISTINCT ON (столбец)`, который оставляет первую строку для каждого значения столбца; для предсказуемости ему нужен `ORDER BY`.

### 10. Как сгенерировать большой объём тестовых данных средствами PostgreSQL?

Проще всего использовать `generate_series` вместе с `INSERT ... SELECT`:

```sql
INSERT INTO products (seller_id, category_id, title, price)
SELECT 1,
       2,
       'Товар №' || g,
       (1000 + g * 10)::numeric(12, 2)
FROM generate_series(1, 1000) AS g;
```

Для псевдослучайных значений применяют `random()`, при необходимости фиксируя зерно через `setseed()`. Для воспроизводимости лучше использовать детерминированные выражения от `g`. Массовую вставку удобно выполнять в одной транзакции, а после явной вставки ID — синхронизировать последовательности через `setval`.
